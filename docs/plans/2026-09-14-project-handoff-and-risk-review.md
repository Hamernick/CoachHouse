## AI permissions, prompt injection, and escape assessment

“AI escapability” is interpreted here as unintended tool execution, exceeding user/tenant permissions, leaking data, uncontrolled spending, or persisting autonomous activity. No exploit, prompt-injection test, destructive query, or live model invocation was performed.

1. **Development agent: high-impact permissions already exist.** This session uses unrestricted filesystem/network access and an approval policy that does not automatically prompt. The agent can run commands and use authenticated GitHub/Supabase/browser tools. AGENTS.md is behavioral guidance, not an OS sandbox. A malicious page/document or an agent mistake must not be allowed to redefine authorization. For stronger protection, use a restricted runtime/worktree, narrowly scoped non-production credentials, and enforced approval for production mutations. Keep main protection and independent review. No actual sandbox escape is needed to cause damage when access is already broad.
2. **App AI SQL: priority security follow-up, pre-existing on main.** The admin editor takes generated SQL and immediately invokes runQuery with readOnly:true ([SQL editor](../../src/components/sql-editor.tsx#L86)). The API checks the signed-in user's database role and configured project ([authorization](../../src/lib/supabase/management-api-auth.ts)), then sends schema names/types and the user's prompt to OpenAI ([generation route](../../src/app/api/ai/sql/route.ts#L74)). The query proxy forwards the caller's body using the server Management API token ([proxy](../../src/app/api/supabase-proxy/[...path]/route.ts#L43)); read-only is not independently forced there. This is not evidence that an ordinary member can bypass admin authorization or that read-only SQL is ignored. It is a broad admin trust boundary with automatic model-output execution. Recommend explicit SQL review, a dedicated server-enforced read-only role/route with restricted tables/functions, output/row/time limits, and audit records before expanding its use.
3. **AI configuration/data limits are incomplete in that route.** The UI feature flag is not checked by the API itself. The route does not declare prompt length, per-user rate limits, output-token limits, or store:false. Current provider keys/production activation/retention settings were not inspected. Treat schema and administrator-entered prompt text as outbound data; do not claim all app AI is off because its button is hidden. No returned SQL results are sent back to the model in the reviewed flow.
4. **Resource enrichment has stronger boundaries.** The reviewed CLI defaults to no network, uses explicit network/write flags, caps batches at 100 (default 5), uses structured output and supplied-URL checks, marks source text untrusted, and sets store:false. The owned crawler requires the exact plan hash plus network/write flags and includes private-network checks. These reduce risk; a second model's approval and schema validation do not prove factual truth or immunity to injected source text. Keep deterministic provider evidence and publication review. No model-tool loop or autonomous shell execution was found in these reviewed model calls.
5. **Other security gaps worth a separate pass.** Sampled production HTML responses had HSTS but no CSP, X-Frame-Options, or X-Content-Type-Options. Source has a few route-specific nosniff headers but no global CSP in the inspected configuration. This is a missing defense layer, not proof of exploitable XSS/clickjacking. Test a compatible policy with Google, Mapbox, embeds, and payments before enforcement. The admin Supabase factory also lacks a server-only import marker; add an enforceable module boundary in a focused review, without claiming the key is currently in client bundles.

The historical release-security runbook records remediation of ten August findings; that does not certify today's branch. Its alert delivery, named backup ownership, and rollback evidence remain unverified in this assessment. A full current-commit security scan, dependency-advisory check, cross-tenant attack validation, and secret-history audit were not performed here.
