# Particle Event calendar extension

This section documents the Event calendar addition, not the complete application schema.

- Canonical Events: validated Activity Event widgets in `organization_workspace_boards.state.particleGraph`; projected into the internal calendar without duplicate event rows.
- `organization_workspace_calendar_revisions`: `org_id UUID PRIMARY KEY` referencing `organizations(user_id)` with cascade; `revision BIGINT > 0`; `updated_at TIMESTAMPTZ`. One small invalidation signal per organization, no Event content.
- Forced RLS, authenticated organization-scoped SELECT only, no anonymous access or client writes. The transactional board trigger checks calendar permissions and increments signals only for semantic Event changes. Only this signal table is published to Realtime.
- Migration/rollback and verification: [receipt](plans/2026-10-14-particle-event-calendar-migration-receipt.md).

# Workspace page membership extension — applied October19

- `organization_workspace_pages` belongs to `organizations(user_id)` with cascade. A stable UUID page ID and organization-scoped unique `link_id` identify the page; selected Particle UUIDs form an explicitly ordered array of 1–50 distinct values. No source records or graph geometry are copied.
- Draft `title`, `description` and `particle_ids` are separate from `published_snapshot`/`published_at`. Visibility defaults to Private; Public requires committed snapshot content. Revision is a positive integer; timestamps use `TIMESTAMPTZ`.
- Forced RLS permits only same-organization owner/admin/staff reads. Anonymous users have no table access; authenticated clients have no direct write privileges. Service-role writes will be reachable only through the authorized publication writer. No Realtime publication, storage bucket, Google permission mutation or response table is added.
- Migration: `20261016183000_workspace_page_membership.sql`; matching rollback removes only the new page table/helper. Isolated fixture: `supabase/tests/workspace-sharing.test.sql`. **Applied and independently verified on Coach House Production October19.** [Current implementation boundary](plans/2026-10-16-workspace-board-sharing-mvp.md).
- `20261016190000_workspace_page_commit.sql` adds latest-operation UUID/actor/hash receipt columns and service-only `commit_workspace_page`. Current membership, page revision, graph identity/content and organization freshness are checked under row locks. Publish replaces the snapshot; draft saves preserve it; Private revokes visibility independently of source availability. Replays return the confirmed commit; older requests cannot undo a later operation. No history collection or Realtime feed. Matching rollback removes only the writer/receipt columns, retaining pages. Isolated SQL and independent-session tests pass; **also applied and independently verified October19**. Full public JSON validation remains in the server projection.
- S20 extends that writer with locked canonical Drive metadata, exact profile checks for Core Documents and a current organization-handle claim check. `20261018120000_workspace_page_public_read.sql` adds a service-only bounded reader: current Public visibility + matching unreserved organization handle; returns only the committed snapshot and publication timestamp. No draft selection, private revision, source row, token or upload path. The server validates the result and rejects ungranted assets/noncanonical links. No anonymous table/RPC grant or new storage. Reader rollback removes only the function. All three sharing migrations were **applied and independently verified on Production October19**; current isolated fixtures cover source changes, handle ownership/reservations, revocation, raw access denial and rollback. The reader was renamed before application on October18: production timestamp `20261016200000` already belongs to fiscal review/tasks/CC and must not be reused.
